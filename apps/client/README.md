# Client

React frontend for the TODO app, built with Vite, TypeScript, Redux Toolkit Query and shadcn/ui. It is part of a pnpm + Turborepo monorepo and talks to the Express API in `apps/server`.

## Features

- List all todos, newest first, with a count of remaining todos
- Create and edit todos in a dialog (title required, description optional)
- Mark todos as done or not done; completed todos are faded and struck through
- Delete todos after a confirmation dialog
- Shows the date each todo was created
- Optimistic updates: changes appear immediately and roll back if the server rejects them
- Loading skeletons, an error state with a Retry button, and an empty state
- Form validation with inline error messages, plus toast notifications for success and failure

## Prerequisites

- Node.js 22.12 or newer
- pnpm 11 (`corepack enable` picks up the version pinned in the root `package.json`)
- The API from `apps/server` running and connected to MongoDB (see [`apps/server/README.md`](../server/README.md))

## Setup

From the repository root:

```bash
pnpm install
cp apps/client/.env.example apps/client/.env   # optional, see below
```

## Running

| Command (from the repo root)     | What it does                                                |
| -------------------------------- | ----------------------------------------------------------- |
| `pnpm dev`                       | Starts the client **and** the API in watch mode (Turborepo) |
| `pnpm --filter client dev`       | Starts only the client at `http://localhost:5173`           |
| `pnpm --filter client build`     | Type-checks and builds a production bundle into `dist/`     |
| `pnpm --filter client preview`   | Serves the production build locally                         |
| `pnpm lint` / `pnpm check-types` | ESLint / TypeScript checks across the monorepo              |

## Environment variables

| Variable       | Required | Default                     | Description         |
| -------------- | -------- | --------------------------- | ------------------- |
| `VITE_API_URL` | no       | `http://localhost:5000/api` | Base URL of the API |

The default matches the server's default port, so no `.env` file is needed for local development. Vite inlines `VITE_` variables at build time, so changing the URL requires a rebuild.

## Architecture

```

├── App.tsx                      # page header with the "New todo" button, and the list
├── app/
│   ├── api.ts                   # RTK Query base API (fetchBaseQuery + VITE_API_URL, "Todo" tag)
│   └── store.ts                 # Redux store with the API reducer and middleware
├── features/todos/
│   ├── todosApi.ts              # endpoints: getTodos, createTodo, updateTodo, toggleTodo, deleteTodo
│   ├── schemas.ts               # zod schema shared by the create and edit forms
│   ├── types.ts                 # Todo, request inputs, API error body
│   └── components/
│       ├── TodoList.tsx         # loading / error / empty states; hosts the shared edit and delete dialogs
│       ├── TodoItem.tsx         # one row: checkbox, title, description, created date, actions
│       ├── TodoDialog.tsx       # create or edit dialog (react-hook-form + zod)

```

### Data flow

The server is the source of truth, and RTK Query caches it on the client. `getTodos` provides one `Todo` tag per item plus a `LIST` tag.

Each mutation updates the cached list in `onQueryStarted` before the request finishes:

| Mutation     | Immediately                               | On success                         | On failure     |
| ------------ | ----------------------------------------- | ---------------------------------- | -------------- |
| `createTodo` | adds the todo with a temporary `temp-` id | swaps in the todo the server saved | `patch.undo()` |
| `updateTodo` | applies the new title / description       | swaps in the server's version      | `patch.undo()` |
| `toggleTodo` | flips `done`                              | swaps in the server's version      | `patch.undo()` |
| `deleteTodo` | removes the todo                          | nothing else to do                 | `patch.undo()` |

The API layer has no UI side effects. Components call `mutation(...).unwrap()` and show toasts with sonner, using `getErrorMessage()` to turn API errors into readable messages (for example "Title is required" or "Can't reach the server").

### UI

All UI is built from shadcn/ui components (Card, Item, Dialog, AlertDialog, Field, Checkbox, Empty, Alert, Badge, Skeleton, Spinner) on Tailwind CSS v4. Forms use react-hook-form with a zod schema that mirrors the server's validation.

## Assumptions and limitations

- **Single user:** there is no authentication, and everyone using the same API sees the same list.
- **No pagination or filtering:** the whole list is loaded at once, which is fine at TODO-list scale.
- **Unsaved todos are read-only:** a todo that is still being created (temporary id) can't be toggled, edited or deleted until the server confirms it.
- **Delete is permanent:** it asks for confirmation, but there is no undo.
- **Light theme only:** the shadcn theme includes dark-mode styles, but there is no theme switcher.
- **No automated tests:** the features were tested manually against the API and a local MongoDB.
